## Findings fixed

Each was checked at the Silicon Doc line: event list 2276-2291, selectable events 2231 and 2255, WAITQMT 2102,
JQMT 2121, CT 2137.

- **`event_interrupt_config.yaml`:** "16 selectable event sources" (four are selectable); "Smart Pin ready" as a
  mode and a typical use. `AKPIN` goes from the SE1 pin example: the event is on the pin's INA/INB bit.
- **`event_system.yaml`:** "every event but 15" had a Jxxx branch; event 15 has JQMT/JNQMT.
- **`interrupts.yaml`, `event_system.yaml`:** smart-pin IN named as the event source; the source says the INA/INB bit.
- **All three:** `CT >= CTn` becomes CT passing CTn. `%01_000000` becomes the source's `%001_PPPPPP`, the same value.

## Finding rejected

**`event_system.yaml` `%10_000000` as "is low".** Pass 2 read it as the source's `%10x_PPPPPP`. It is 8 bits, equal to
`%010_000000`, the source's "falls", so "Negative edge" was right. It is written in the source's form anyway.

## Why six passes missed it

Pass 2 of v1.25.2 read the page whole and was asked about interrupt claims. It was not asked to compare tables to
the source table. A row-by-row request found it and more, so §1.5's whole-page read should ask for that when a page
restates a source table.

## What was not checked

Legality only for the changed fragments, and nothing was run on a P2.
